# Rate limiter

This project uses a reusable in-memory sliding-window limiter that exposes `allow(key)` and accepts an injected clock, making its behaviour deterministic in tests. Requests are isolated by `x-api-key` (falling back to client IP) and the Express API returns HTTP 429 when a client exceeds five requests per minute. Run `npm run test:server` for the limiter tests, then `npm run build` and `npm run start:server` to serve the compiled client and API together. It is ready to deploy as a single Node service because the client calls the relative `/api/test` path instead of a local URL. For a multi-instance deployment, I would replace the in-memory request store with an atomic shared store such as Redis and use its expiration support for cleanup.
